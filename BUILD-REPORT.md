## 2. Порядок секций

Требуемая последовательность: шапка → контекст и задача → исходный сценарий →
исследование → выводы → принцип решения → структура → ключевые экраны →
проверка → результаты → навигация.

| Кейс | Секции |
| --- | --- |
| Alif | исследование (шаги + таблица интервью + два вывода) → разделы кабинета → добавление товара → от заявки к передаче → чат → мобильная версия → итоги |
| EAJ | с чего началась работа (маршрут + таблица типов) → главная → карточки или таблица → Funding → обращения → итоги |
| Namaste | исследование + вывод → **структура** → выбор занятия → от списка к тренировке → health-функции → проверка с пользователями → итоги |
| 360 Tracker | с чего начали (шаги + таблицы конкурентов) → **структура** → карта → событие → чаты → приватность → история → итоги |

**Отступление.** В Namaste структура стоит сразу после исследования, а не после
отдельного блока «состав MVP»: состав первой версии определяет вывод из
исследования («короткий опрос → подходящая программа»), отдельной секции под
это в материалах нет. Экраны health-функций идут после структуры, как и
остальные экраны.

У Alif и EAJ отдельной схемы в материалах нет. Роль структуры играют
«Разделы под задачи магазина» (Alif) и «Основной маршрут в кабинете» (EAJ) —
обе стоят до демонстрации экранов.

* Внутренние поля кадра: `clamp(24px, 3.4vw, 44px)` → `clamp(12px, 1.2vw, 18px)`.
  Высота контейнера теперь задаётся изображением, фиксированных высот нет.
* Тень при наведении убрана, осталась смена цвета границы. Скругление и тонкая
  граница сохранены.
* Подпись вынесена из белого контейнера: строка под кадром, вторичный стиль,
  одно предложение.
* «Нажмите, чтобы рассмотреть» заменено на ссылку **«Открыть изображение»**.
  Изображения действительно открываются в лайтбоксе.
* Схемы приложений показываются без белой рамки (`.case-fig--plain`): у них
  своя подложка внутри растра, вторая читалась бы как вложенная карточка.

### Обрезка технического поля в экспортах

Все опубликованные экспорты содержали прозрачное поле по краям — от 1,5 % до
13 % от стороны. Оно обрезано по содержимому, PNG-исходники не тронуты.
В группе (языковая пара, набор тем слайдера) рамка общая и считается в долях,
иначе светлая и тёмная версии разошлись бы по пропорции.

Итог: 54 файла, 12,2 МБ → 10,5 МБ. Пропорция набора Namaste изменилась
с 2940 × 1928 на 2700 × 1768, `aspect-ratio` слайдера обновлён.

## 6. Итоги

Тёмная полоса во всю ширину экрана, контент остаётся в основном контейнере.
Полоса нарисована `box-shadow: 0 0 0 100vmax` с `clip-path: inset(0 -100vmax)`:
это не влияет на раскладку и не создаёт горизонтальной прокрутки, в отличие
от приёма с `100vw`.

| Элемент | Значение |
| --- | --- |
| Фон секции | `#211B18` |
| Фон карточки | `#2C2723` |
| Граница карточки | `rgba(255,255,255,0.11)` |
| Скругление | `--radius-medium`, 20 px |
| Внутренние отступы | `clamp(28px, 2.6vw, 40px)` |
| Сетка | 2 × 2, карточки одного ряда равны по высоте |

Карточка: точка акцента и лейбл прописными → белый заголовок решения →
серое описание → тонкая полупрозрачная линия → «ВЛИЯНИЕ ОЦЕНИВАЛИ ПО»
и метрика обычным серым текстом. Тяжёлых теней нет.

Точка в карточке — акцент своего кейса: фиолетовый у Namaste и 360 Tracker
(как в референсе), жёлтый у Alif, синий у EAJ. Это тот же цвет, что у номеров
шагов и засечек на всей странице кейса.

Из всех четырёх кейсов удалена фраза «Показатели в карточках предложены для
дальнейшей проверки. Измеренный эффект в материалах не приведён.»
Формулировки «Что проверить» нет нигде.

**Заголовки карточек написаны мной.** В правке у карточки есть лейбл,
предложение и метрика, а требуемая структура просит ещё «основной заголовок».
Каждый — сжатие её же предложения, без новых утверждений. Все шестнадцать
лежат в `content.json`, поле `cards[].title`.

## 12. Файлы

| Файл | Что это |
| --- | --- |
| `content.json` | Русский текст и структура блоков. Источник сборки |
| `content.en.json` | Английский перевод. **Не утверждён, нужна вычитка** |
| `build-cases.py` | Сборка четырёх страниц: `python3 build-cases.py` |
| `tools-patch-css.py` | Компонентный CSS кейсов для четырёх страниц. Навигации не касается |
| `tools-restore-nav.py` | Восстановление нижней навигации из git HEAD |
| `tracker_tables.html` | Две таблицы сравнения конкурентов 360 Tracker |
| `assets-manifest.json` | Реестр материалов пакета (справочный) |
| `ASSET-MAP.md` | Сопоставление реестра с файлами репозитория |

Все три скрипта идемпотентны. Порядок запуска:

```
python3 build-cases.py        # содержимое <div class="case-page">
python3 tools-patch-css.py    # компонентный CSS, блок между маркерами «Редакция 3.2»
python3 tools-restore-nav.py  # нижняя навигация строго из git HEAD
```

`build-cases.py` не трогает ничего за пределами `case-page`; CSS-патч
ограничен маркерами и не содержит ни одного правила навигации;
`tools-restore-nav.py` только возвращает компонент из HEAD.

# DESIGN.md — Madina Rashidova Portfolio

## 1. Источник визуальной системы

Главный визуальный референс проекта:
`reference/main-page-web.svg`

Использовать SVG как источник:

* композиции;
* визуальной иерархии;
* цветов;
* размеров;
* пропорций;
* геометрии орбит;
* размещения логотипов;
* оформления интерактивных элементов;
* общего характера интерфейса.

Не вставлять весь SVG на страницу как одну статичную картинку. Восстанавливать дизайн с помощью HTML, CSS, JavaScript и отдельных inline SVG-элементов.

Все интерактивные элементы должны оставаться настоящими ссылками или кнопками.

## 2. Характер дизайна

Портфолио должно ощущаться как работа продуктового дизайнера с сильным визуальным и системным мышлением.

Основные качества:

* точность;
* минимализм;
* спокойствие;
* технологичность;
* системность;
* выразительная композиция;
* редакционная подача;
* внимание к деталям;
* функциональная анимация.

Интерфейс не должен выглядеть как типовой SaaS-сайт или шаблонное AI-портфолио.

Индивидуальность создаётся через:

* орбитальную композицию;
* контролируемое движение;
* крупные обложки проектов;
* контраст светлых и тёмных сцен;
* аккуратную типографику;
* продуманную последовательность появления элементов.

Тёмные поверхности должны иметь тёплый коричнево-чёрный оттенок. Не использовать чистый `#000000` для крупных UI-поверхностей.

### Разделители и орбиты

```css

--color-line-default: #ECECEC;
--color-line-soft: #F1F1F1;
--color-line-faint: #F5F5F5;
```

### Акцент

Основной интерфейс остаётся нейтральным. Цвет используется только:

* внутри фирменных логотипов;
* в проектных обложках;
* для отдельных осмысленных состояний;
* в элементах, уже предусмотренных макетом.

Цвета логотипов из SVG, включая синий, оранжевый, фиолетовый и зелёный, не являются общими цветами интерфейса. Не использовать их автоматически для кнопок, ссылок, фонов или градиентов.

Не добавлять стандартные сине-фиолетовые AI-градиенты.

## 4. Типографика

Сначала проверить, какой шрифт уже подключён в проекте и использован в текущем портфолио.
Не подключать новый шрифт без необходимости и подтверждения.

Основные принципы:

* нейтральный современный grotesk;
* высокая читаемость;
* крупные заголовки;
* спокойный контраст размеров;
* короткие строки;
* минимум декоративных начертаний.

**Актуальная унифицированная шкала** (реализована как identical `:root`-токены,
скопированные во все 5 страниц — about.html и 4 страницы кейсов; на статичном
сайте без сборки и общих include это единственный способ держать систему без
расхождений между файлами, см. PRODUCT.md):

```css
--font-size-h1: clamp(40px, 5vw, 72px);      /* h1.case-title — один H1 на кейс-странице */
--font-size-h2: clamp(24px, 2vw, 30px);       /* .detail-head h2 — нумерованные секции кейсов */
--font-size-h3: clamp(20px, 1.5vw, 24px);     /* .detail-kicker — третий уровень заголовка секции */
--font-size-h4: clamp(19px, 1.6vw, 23px);     /* .case-headline (задача под H1, все 4 кейса) и
                                                   about.html: .about-hero/.about-outside h4
                                                   ("Из поддержки...", "Что мне нравится...",
                                                   "За пределами макетов") — общий токен на обеих */
--font-size-body: clamp(16px, 1.1vw, 18px);   /* .detail-block p, .case-dek — только страницы кейсов */
--font-size-label: 14px;                       /* мелкие uppercase-лейблы и метаданные:
                                                   .case-meta-line, .case-facts dt/dd, .case-tags,
                                                   заголовки таблиц и т.п. Исключение (namespace:
                                                   исправлено 2026-08-28, было неверно указано здесь) —
                                                   .case-context-card__label и .result-card__label
                                                   намеренно мельче общего лейбла, хардкод 12px, не
                                                   через токен — дот-буллет метки внутри карточек
                                                   должны быть тише, чем факты/теги в шапке кейса. */
--font-weight-heading: 600;                    /* h1 больше не 700 — единственный overused-bold, который правили */
--line-height-h1: 1.05;
--line-height-heading: 1.2;                    /* h2/h3 */
--line-height-body: 1.55;                      /* только страницы кейсов, см. about.html ниже */
```

**about.html — сознательное расхождение с общей шкалой** (не токены, а конкретные
компонент-специфичные значения, см. инструкцию по типографике about-страницы):

* `h2.about-title` («Мадина Рашидова») — уже не H1: понижен до H2, но со своим
  размером `--font-size-about-name: clamp(32px, 4vw, 39px)` (36–42px desktop /
  30–34px mobile), а не общим `--font-size-h2`. Токен объявлен только в
  `about.html`, больше нигде не переиспользуется. Страница сознательно
  остаётся без H1 — если это когда-нибудь потребуется пересмотреть
  (например, ради a11y-аудита), это отдельное решение, не побочный эффект.
* Основной текст (`.about-dek`, `.about-hero p`, `.about-outside p`) —
  зафиксирован на `16px` / `line-height: 1.6` напрямую, **не** через
  `--font-size-body` (тот у него потолок 18px) — здесь потолок именно 16px.
* Карточки Telegram-каналов — `.channels-frame` > `.channels-grid`
  (2 колонки `repeat(2, minmax(0,1fr))` desktop, 1 колонка ≤767px),
  карточки `.tg-card` растянуты на всю колонку и на равную высоту
  (`align-items: stretch`). Заменяет прежний `.outside-grid`/`.tg-cards`
  (текст + узкая правая колонка карточек), который оставлял пустое поле
  слева от карточек.

Декоративные/редакционные элементы вне пятиуровневой системы (`.about-quote`,
`.problem-statement` — pull-quote в Alif Partners, `.detail-num` — декоративный
номер секции) сознательно не унифицированы: они не часть читательской иерархии.

Не использовать:

* слишком большое количество размеров;
* uppercase для длинных текстов;
* слабоконтрастный серый текст;
* центрирование длинных описаний;
* искусственное растягивание букв.

--space-5: 24px;
--space-6: 32px;
--space-7: 48px;

Использовать:

* `4–8px` для внутренних микроинтервалов;
* `16–24px` между связанными элементами;
* `32–64px` между смысловыми группами;
* `96–128px` между крупными секциями.

Максимальная ширина основного контента:

```css

```

Горизонтальный отступ страницы:

```css
--page-padding: clamp(20px, 4vw, 80px);
```

Не использовать случайные значения, если их можно привести к системе.

* жёсткие чёрные тени;

## 10. Орбитальная система

В SVG используются пять орбит:

| Орбита | Центр X | Центр Y |  Радиус | Линия     |
| ------ | ------: | ------: | ------: | --------- |
| 1      |     960 | 466.667 |     266 | `#EAEAEA` |
| 2      |     960 | 493.334 |     426 | `#EAEAEA` |
| 3      |     960 |     520 |     586 | `#ECECEC` |
| 4      |     960 | 546.667 |     746 | `#F1F1F1` |
| 5      |     960 | 573.334 | 906.333 | `#F5F5F5` |

Использовать одну координатную систему с:

```text
viewBox="0 0 1920 1080"
```

Логотипы должны двигаться строго по видимым окружностям.

Формула:

```text
x = centerX + radius × cos(angle + phase)
y = centerY + radius × sin(angle + phase)
```

Рекомендуемые продолжительности:

| Орбита | Полный оборот | Направление    |
| ------ | ------------: | -------------- |
| 1      |           42s | по часовой     |
| 2      |           58s | против часовой |
| 3      |           72s | по часовой     |
| 4      |           88s | против часовой |
| 5      |          110s | по часовой     |

Движение:

* медленное;
* непрерывное;
* линейное;
* с разными начальными фазами;
* без резких изменений скорости.

Карточки и логотипы остаются вертикальными и не вращаются вокруг своей оси.

Не использовать случайное свободное движение, не связанное с линиями.

## 11. Контейнеры логотипов

Базовый размер на desktop:

```css
--orbit-item-size: 86px;
```

Форма:

* круглая;
* полупрозрачная белая поверхность;
* мягкая тень;
* отсутствие тяжёлой обводки;
* логотип выровнен по центру.

Пример:

```css
.orbit-item {
  width: var(--orbit-item-size);
  aspect-ratio: 1;
  display: grid;
  place-items: center;
  border-radius: 50%;
  background: rgba(255, 255, 255, 0.65);
  box-shadow: var(--shadow-soft);
}
```

Логотипы масштабировать пропорционально. Не растягивать и не перекрашивать фирменные знаки.

## 12. Вступительная анимация

Последовательность:

1. Появляется основной фон.
2. Появляется верхняя навигация.
3. Орбитальные линии проявляются от центра к краям.
4. Контейнеры логотипов появляются с небольшим stagger.
5. Появляется центральный заголовок.
6. Появляются контактные действия.
7. Начинается постоянное движение логотипов.

Общая длительность:

```text
1.6–2.4 секунды
```

Для появления:

```css
cubic-bezier(0.22, 1, 0.36, 1)
```

Для орбит:

```css
linear
```

Не использовать:

* bounce;
* elastic;
* резкое масштабирование;
* чрезмерный blur;
* длинный preloader;
* scroll hijacking;
* хаотичное движение.

## 13.1 Hero / Orbit Stage — исключение стекла

Главный экран (`.hero`, `.orbit-stage`, `.name-stack`) — единственная зона сайта, где glassmorphism разрешён вне `.case-navigation`. Это осознанное, зафиксированное здесь решение, а не отклонение без документации.

**Разрешено на:**

* `.logo-card` (контейнеры логотипов на орбитах);
* `.job-search-status` (статус поиска работы, см. §13.6).

**Запрещено** распространять стекло на любые другие секции, карточки или кнопки за пределами главного экрана и `.case-navigation` — при конфликте с общим Impeccable-антипаттерном «не злоупотреблять стеклом», побеждает это явное исключение, а не detector.

**Контраст.** Текст на стекле — тёмный (`--hero-text`, `#231e1b`), либо акцентный `--live` только для маленькой live-точки; крупный светлый текст на этом светлом стекле не используется.

**Производительность.** `backdrop-filter` применяется только к `.logo-card` (11 элементов, круглые, малого размера) и `.job-search-status` (один элемент) — не к крупным поверхностям, чтобы blur не стоил дорого при перерисовке орбит.

## 13.2 Fixed navigation layers

Слои сайта, закреплённые (`position: fixed`) поверх скролла, и их место в общей системе слоёв (см. §13.7):

* верхняя навигация `.site-nav` — `z-index: 100`, на всех страницах;
* плавающий док `.case-floating-nav` — `z-index: 110`, на 4 страницах кейсов и на `about.html` (см. §13.3); не выводится на `index.html`;
* lightbox — `z-index: 200`, поверх обоих.

Оба закреплённых слоя (nav, док) должны:

* оставаться доступными с клавиатуры при любом положении скролла;
* не перекрывать смысловой текст навязчиво — верхняя навигация может визуально лежать на декоративной части обложки, но не на заголовке или описании проекта;
* сохранять контраст текста независимо от того, светлая или тёмная сцена находится под ними;
* не менять высоту/положение при переключении языка.

Safe-area отступы для контента вокруг них:

```css
--fixed-nav-top-safe-area: 120px;
--fixed-nav-bottom-safe-area: 100px;
```

На страницах кейсов нижний safe-area реализован через `.case-page { padding-bottom: 160px; }`. На главной верхний safe-area реализован через `.project-chapter--alif { scroll-margin-top: var(--fixed-nav-top-safe-area); }` — переход по ссылке «Работы →» на `#work` не прячет заголовок первой сцены под навигацией.

## 13.3 Floating case controls

Панель case-навигации — это **два самостоятельных плавающих glass-контрола**, а не одна большая секция-панель. Актуальная реализация (заменяет любые более ранние описания единой плашки); см. § «Case navigation (Home/Prev + Next case)» для полного описания разметки и того, какая страница показывает какой левый контрол.

```css
.case-floating-nav {
  position: fixed; left: 50%; bottom: max(20px, env(safe-area-inset-bottom));
  transform: translateX(-50%);
  z-index: 110; display: flex; gap: 10px;
  max-width: calc(100vw - 32px);
}
```

* Общего непрозрачного/полупрозрачного фона у `.case-floating-nav` нет — `background`, `border`, `box-shadow`, `backdrop-filter` заданы отдельно на левый контрол (`.case-home` на Alif Partners, `.case-prev` на остальных трёх) и на `.case-next`, каждый — самостоятельная капсула.
* Оба контрола используют одну и ту же формулу стекла: `rgba(255,255,255,0.62)` + `blur(20px) saturate(125%)` + тонкая светлая обводка + мягкая тень. Fallback без `backdrop-filter`: `rgba(248,248,248,0.94)`.
* Появление — одноразовый fade+translateY при загрузке страницы (как верхняя навигация), не привязано к скроллу: плавающий элемент не «появляется при приближении», он уже над контентом.
* На узких экранах (`max-width: 720px`) подписи `.case-next__label`/`.case-prev__label` («Следующий кейс» / «Next case», «Предыдущий кейс» / «Previous case») скрываются визуально (`sr-only`-паттерн), оставаясь доступными для скринридера — видимый текст сокращается до названия кейса и стрелки.
* Скрывается (`opacity: 0; pointer-events: none`) через `body.lightbox-open .case-floating-nav`, когда открыт lightbox — не должен оставаться кликабельным под модальным изображением.
* Никогда не превращается в отдельную секцию документа и не выводится на `index.html` — существует на 4 страницах кейсов и на `about.html` (там — `.case-home` + `.case-next` со ссылкой на `index.html#work`, "Смотреть кейсы"/"See the work"), для перехода на главную/предыдущий/следующий кейс или к списку работ. Никакой функции «лайка» на сайте нет (см. § «Case navigation (Home/Prev + Next case)»). Короткие вьюпорты по высоте (≤850px/≤740px) получают такую же компактную версию вертикальных отступов над доком, как и страницы кейсов — см. `@media (max-height: ...)` в конце `<style>`-блока `about.html`.

## 13.4 Content Safe Zones (Project content safe zones)

Каждая проектная сцена задаёт собственную ширину текстовой колонки — общая формула `min(520px, 34vw)` держит измерение в районе 50–65 символов на строку, конкретные сцены сужают/смещают его там, где обложка требует:

```css
.project-showcase__body { max-width: min(520px, 34vw); } /* базовое ориентировочное значение */
.project-showcase--alif    .project-showcase__body { max-width: min(480px, 34vw); }
.project-showcase--eaj     .project-showcase__body { max-width: min(420px, 32vw); margin-top: 48px; }
.project-showcase--namaste .project-showcase__body { max-width: min(460px, 34vw); }
.project-showcase--tracker .project-showcase__body { max-width: min(440px, 32vw); }
```

Минимальная защитная зона между текстовой колонкой и главным объектом обложки (ноутбук/планшет/смартфон/портреты) — `48px`, обеспечивается сочетанием ширины колонки выше и `object-position` кадра (§13.9). EAJ Trader — самый узкий случай: обложка с ноутбуком, смещённым правее центра (`object-position: 76% 55%`); полноширинная колонка текста заходит на экран ноутбука. Сужение и сдвиг фокуса кадра вправо держат текст в тёмной зоне слева, не пересекая границу устройства.

На узких экранах (`max-width: 760px`) формула ширины колонки перестаёт действовать — см. § Responsive Project Scenes (в §20): там текст физически переносится под изображение, а не сужается дальше внутри него.

Правило на будущее: если новая обложка или новый кроп конфликтует с текстовой колонкой, порядок действий: 1) сузить `.project-showcase__body` конкретного проекта через модификатор класса; 2) скорректировать `object-position`; 3) сократить короткое описание на главной без потери смысла; 4) только после этого усиливать локальный `.project-showcase__scrim` (§15) — глобальное затемнение не первый инструмент.

## 13.5 CTA Spacing (Content-to-CTA spacing)

Кнопка «Подробнее» / «See details» никогда не садится впритык к последней строке описания. Один интервал на всех четырёх обложках, обычными `margin`, не завязанный на состояние анимации:

```css
.project-showcase__desc     { margin-top: clamp(24px, 2.5vw, 32px); } /* мета → описание: 24–32px */
.project-showcase__cta-wrap { margin-top: clamp(32px, 3vw, 40px);  } /* описание → кнопка: минимум 32px */
```

Минимум `32px` для description → CTA держится на всех брейкпоинтах: `clamp()` не опускается ниже 32px даже там, где бриф допускал бы 28px (medium) или 24px (mobile) — единый более строгий пол проще поддерживать, чем три отдельных точки, и не противоречит ни одному из требований (32 ≥ 28 ≥ 24). Это управляемый интервал, не побочный эффект entrance-анимации: `margin-top` всегда на месте независимо от того, в какой фазе scroll-progress сейчас находится opacity/translateY элемента (§ Scroll Progress and Layering) — кнопка не «прыгает» относительно текста во время появления. При многострочном описании (перенос на дополнительную строку) отступ остаётся тем же — он задан от края блока `.project-showcase__cta-wrap`, а не «после последней строки текста».

Кнопка — минимум `56px` высотой (`min-height: 56px`, при `padding: 0 28px`), что превышает минимальную область нажатия `44×44px`; видимые состояния `:hover`/`:focus-visible`/`:active` заданы для каждого варианта кнопки (светлого и тёмного, см. §13.9).

## 13.6 Job search status

Статус поиска работы — **не badge с зелёной точкой**, а компактный glass-индикатор с метафорой лупы, над именем в hero:

```css
.job-search-status {
  display: inline-flex; align-items: center; gap: 10px;
  min-height: 44px; padding: 10px 18px 10px 14px; border-radius: 999px;
  background: rgba(255, 255, 255, 0.62);
  border: 1px solid rgba(255, 255, 255, 0.78);
  box-shadow: 0 10px 32px rgba(23, 17, 14, 0.08), inset 0 1px 0 rgba(255, 255, 255, 0.72);
  backdrop-filter: blur(18px) saturate(120%);
  color: #231e1b;
}
```

**Текст.** RU: «Ищу продуктовую команду». EN: «Looking for a product team». Без uppercase, без длинного предложения, без зелёной точки как главного элемента.

**Иконка.** Инлайн SVG лупы (`.job-search-status__icon`), не эмодзи. Маленькая зелёная live-точка (`.job-search-status__live`, `--live`) допущена как второстепенная деталь в углу иконки — не заменяет её, не крупнее лупы.

**Микроанимация.** Только на иконке (`.job-search-status__icon svg`), не на всём pill — короткий «взгляд украдкой», раз в ~5 секунд:

```css
@keyframes searchGlance {
  0%, 75%, 100% { transform: translateX(0) rotate(0); }
  82% { transform: translateX(3px) rotate(-3deg); }
  90% { transform: translateX(-1px) rotate(2deg); }
}
```

Никакого непрерывного вращения, bounce, мигания или масштабирования. `prefers-reduced-motion: reduce` отключает и entrance-fade, и `searchGlance` — статус остаётся статично видимым.

**Интерактивность.** Не интерактивен и без `tabindex` — три контактные кнопки (Telegram/Email/CV) прямо под ним уже владеют действием «связаться»; добавлять тот же переход на сам статус было бы избыточным вторым путём к одному и тому же действию, а не отдельной функцией.

**Расстояния.** От статуса до имени — `26px` (`.name-stack` gap); статус не шире заголовка и не растягивается на всю ширину блока (`width: fit-content` через `inline-flex`).

## 13.9 Project Cover Composition

Каждая обложка — фотография с одним читаемым устройством/объектом (планшет, ноутбук, смартфон, две портретные метки) и текстовой колонкой в свободной зоне рядом. Правила на проект:

```text
Alif Partners  — object-position: center 42%; текст слева/снизу, планшет не закрыт.
EAJ Trader     — object-position: 76% 55%; ноутбук смещён правее центра, текст слева,
                 экран ноутбука должен оставаться читаемым и визуальным центром кадра.
Namaste        — object-position: 58% 32%; смартфон по центру, светлая сцена
                 (инверсия: тёмный текст, тёмная CTA-кнопка — см. §13.5/§17).
360 Tracker    — object-position: 42% 46%; смартфон + два круглых портрета по центру-слева,

```

Локальное затемнение (§15) кладётся только в зоне текста, направленным градиентом от края к центру — не общим потемнением всей фотографии; степень затемнения подбирается так, чтобы текст оставался читаемым, а обложка не превращалась в почти чёрный/белый фон.

**EAJ Trader — открытый вопрос, статус на 2026-08-28.** Ранее была запрошена замена обложки на новый файл; на тот момент его не было ни в проекте, ни в `~/Downloads`, поэтому замена была отложена. Файл `assets/eaj trader new.png` с тех пор появился в `assets/`, но решение о замене обложки не принято — актуальная домашняя страница по-прежнему использует `assets/eaj-trader-cover.png` (с `object-position: 76% 55%`, атрибуты `width="3000" height="2000"` уже заданы). Композиционные правила выше (текст слева, экран читаем) переносятся на новую фотографию без изменений в день, когда будет принято решение её использовать.

## 13.8 Stacked Project Transitions

Промежуточный экран «Работы» удалён — при скролле вниз hero сразу продолжается первой проектной сценой. Механика заменена (Round 3) с «sticky-глава per проект» на настоящий Floema-style стек полноэкранных панелей: одна сцена физически поднимается снизу и **накрывает** предыдущую как отдельный слой, а не сменяет её в обычном вертикальном потоке.

```css
.projects-stage-wrap.js-stage-active { height: 700vh; height: 700svh; }
.projects-stage-wrap.js-stage-active .projects-stage {
  position: sticky; top: 0; height: 100svh; overflow: hidden; isolation: isolate;
}
.projects-stage-wrap.js-stage-active .project-showcase {
  position: absolute; inset: 0; transform: translateY(var(--ty, 100%));
}
.project-showcase--alif    { --ty: 0%; z-index: 1; } /* сцена 0 — никогда не трогается скриптом */
.project-showcase--eaj     { z-index: 2; }
.project-showcase--namaste { z-index: 3; }
.project-showcase--tracker { z-index: 4; }
```

**Прогрессивное улучшение — два слоя, по умолчанию выключен верхний.** Без класса `.js-stage-active` `.projects-stage-wrap` — обычный `height: auto` блок, и все четыре `.project-showcase` — обычные, полностью видимые full-bleed секции друг под другом (то, что видит не-JS посетитель и `prefers-reduced-motion: reduce`, см. §21). Скрипт добавляет `.js-stage-active` только если он выполнился **и** reduced-motion не включён — на любой ширине экрана, включая мобильную (см. § Responsive Project Scenes) — только тогда сцены становятся абсолютно позиционированными слоями, а `.projects-stage` — приклеенным (`sticky`) окном.

**Порядок и бюджет скролла.** 700svh обёртки = 100svh закреплённого окна + 600svh «протяжки» скролла сквозь неё, разбитых на 3 перехода по 120svh с паузами по 60svh между ними и в начале/конце:

```text
0–60svh     удержание на Alif Partners (сцена 0, статична)
60–180svh   EAJ Trader поднимается над Alif Partners      (переход, 120svh)
180–240svh  удержание, EAJ Trader на месте
240–360svh  Namaste поднимается над EAJ Trader             (переход, 120svh)
360–420svh  удержание, Namaste на месте
420–540svh  360 Tracker поднимается над Namaste             (переход, 120svh)
540–600svh  удержание, 360 Tracker на месте — конец стека
```

Порядок: Alif Partners → EAJ Trader → Namaste → 360 Tracker — совпадает с §14 и с возрастающим `z-index` (§13.7): входящая сцена всегда рисуется поверх той, что уже на месте.

**Локальные фазы одного перехода** (0–100% — прогресс внутри своего 120svh окна, не всей обёртки):

```text
0–10%    сцена ещё полностью ниже вьюпорта (--ty: 100%)
10–70%   физический подъём: --ty едет 100% → 0%, лёгкий --scale 1.03 → 1 на изображении
35–60%   проявляется фон/изображение (--media-o: 0 → 1)
50–72%   номер, метаданные, заголовок (--header-o: 0 → 1)
60–82%   описание (--desc-o: 0 → 1)
70–90%   кнопка (--cta-o: 0 → 1)
90–100%  сцена полностью собрана и удерживается
```

Подъём — основной эффект, текст — вторичный и просто следует за ним; подъём завершается заметно раньше (к ~70% локального прогресса), чем текст (к ~90%), намеренно — сцена физически на месте, пока текст ещё «собирается». Эффект переезда без пружин/bounce — `easeOutCubic` на подъёме, без CSS `transition` (см. следующий раздел).

**Обратный скролл.** Все величины — чистая функция текущей позиции скролла, а не таймер; при скролле назад та же формула в обратную сторону возвращает `--ty` к 100%, и уже поднятая сцена опускается, вновь открывая предыдущую — без специального кода для реверса.

**Fallback hero → первая сцена.** `.hero` не переведён на sticky/stack-механику (его высота и центрирование орбит через `cqw`-математику — защищённая композиция). Alif Partners просто следует сразу за hero в потоке документа с нулевым зазором — первая сцена стека не «въезжает» ни во что, она то, что видно, когда `.projects-stage` только закрепился.

## 13.9a Scroll Progress and Layering

Все визуальные переменные — прямая функция скролла, вычисляемая в одном общем `requestAnimationFrame`-цикле, без CSS `transition` в цепочке (иначе движение сглаживается таймером, а не следует за скроллом 1:1):

```js
var wrapRect = wrap.getBoundingClientRect();
var stuckPx = Math.max(wrapRect.height - vh, 1);
var scrolledPx = clamp01(-wrapRect.top / stuckPx) * stuckPx;
var progressVh = (scrolledPx / vh) * 100; // 0–600, см. бюджет выше
```

Для каждого из трёх переходов локальный прогресс `t = clamp01((progressVh - start) / (end - start))` подаётся в `applySceneVars`, которая пишет `--ty`, `--scale`, `--media-o`, `--header-o`, `--desc-o`, `--cta-o` (и `--mobile-text-o` для мобильного упрощённого фейда, см. §20) через `element.style.setProperty(...)` — CSS читает их через `var(--x, fallback)`, fallback равен «полностью собрано», так что до первого кадра скрипта и в baseline-режиме всё уже видимо.

Обязательно:

* никогда не читает/не устанавливает `scrollTop`, не вызывает `preventDefault` на wheel/touch/scroll — только `getBoundingClientRect`, то есть никакого scroll-hijacking;
* без forced scroll-snap, без авто-прокрутки, без горизонтального скролла;
* цикл останавливается на `visibilitychange` (вкладка скрыта) — тот же принцип, что у орбит (§23);
* `.js-stage-active` гейтится и `prefers-reduced-motion` (§21), и шириной вьюпорта — `matchMedia('(max-width: 767px)')` явно выключает механику на мобильном и переключает её обратно при пересечении границы 767px в любую сторону (см. правку в § Responsive Project Scenes от 2026-08-28, где раньше было обратное утверждение).

Показывать только язык, выбранный текущим переключателем.

Стиль:

```css
.project-link {
  min-height: 56px;
  padding: 0 28px;
  border-radius: var(--radius-pill);
  background: #F8F8F8;
  color: #171717;
}
```

Кнопка содержит:

* текст;
* стрелку направо;
* заметное состояние `focus-visible`.

Hover:

* стрелка смещается вправо на `4px`;
* кнопка поднимается максимум на `2px`;
* контраст немного усиливается.

Не использовать bounce.

Инверсия для сцен с недостаточным контрастом: на светлой обложке Namaste кнопка тёмная со светлым текстом (`background: var(--nav-bg); color: var(--text-inverse)`); на тёмной обложке 360 Tracker используется обычная светлая кнопка. Форма, высота и поведение (hover/focus-visible) остаются едиными для всех четырёх проектов — меняется только цветовая инверсия.

## 18. Scroll-анимация проектов

Последовательность при появлении сцены (проценты — локальный прогресс её собственного перехода, см. § Stacked Project Transitions):

1. 0–10% — сцена целиком ниже вьюпорта.
2. 10–70% — физический подъём сцены (`--ty: 100% → 0%`), изображение `scale(1.03) → scale(1)`.
3. 35–60% — проявляется изображение/затемнение.
4. 50–72% — появляются номер, теги, заголовок, метаданные.
5. 60–82% — появляется описание.
6. 70–90% — появляется кнопка.
7. 90–100% — сцена полностью собрана и удерживается до начала следующего перехода.

Подъём — первичный эффект, текст — вторичный: подъём завершается раньше, текст продолжает проявляться, пока сцена уже физически на месте.

Использовать:

* прямое чтение `getBoundingClientRect` в `requestAnimationFrame`, без `IntersectionObserver` (переходов всего три, порог/накопление состояния не нужны);
* `transform`, `opacity`, CSS custom properties (`--ty`, `--scale`, `--media-o`, `--header-o`, `--desc-o`, `--cta-o`).

Не использовать:

* `preventDefault` для колеса мыши;
* обязательный scroll snap;
* принудительное перелистывание;
* scroll hijacking;
* дрожащий параллакс;
* CSS `transition` в этой цепочке (иначе движение сглаживается таймером вместо прямого следования за скроллом).

## 19. Переходы между сценами

Переходы должны ощущаться как единая история:

```text
Главный экран → Alif Partners → EAJ Trader → Namaste → 360 Tracker
```

Правила:

* отсутствие случайных белых промежутков;
* отсутствие наложения текстов соседних проектов;
* навигация остаётся доступной;
* каждая сцена сохраняет собственную обложку и характер;
* общий motion-язык остаётся единым;
* в любой момент перехода видны части двух сцен одновременно — входящей (сверху, выше по `z-index`) и предыдущей (под ней) — это и отличает переход от обычной вертикальной прокрутки секций.

Переход Namaste → 360 Tracker подчёркивает смену атмосферы (светлая, спокойная сцена → тёмная, технологичная сцена): 360 Tracker физически поднимается над Namaste тем же общим motion-языком, без наложения текстов и без мерцания фона.

Механика самого перехода (стек абсолютно позиционированных сцен, возрастающий `z-index`, бюджет скролла, hero → первая сцена) — § Stacked Project Transitions (13.8), не здесь; этот раздел фиксирует правила результата, не реализацию.

## 20. Адаптивность

### Desktop

* главный экран близок к SVG при `1920 × 1080`;
* показывается полная орбитальная композиция;
* проектные сцены занимают около `100svh`;
* текст располагается в свободной части обложки.

### Tablet

* разрешено обрезать внешние орбиты;
* количество одновременно видимых логотипов можно уменьшить;
* текст проектов становится уже;
* не допускать пересечения с навигацией.

### Mobile

* сохранить центральную идею, а не масштабировать desktop буквально;
* показывать 2–3 основные орбиты;
* часть декоративных логотипов можно скрывать;
* кнопки должны оставаться доступными;
* минимальная интерактивная область — `44 × 44px`;
* горизонтальный скролл запрещён.

### Responsive Project Scenes

**Исправлено 2026-08-28 — предыдущая версия этого пункта утверждала, что механика подъёма работает на любой ширине; аудит нашёл прямое противоречие с кодом и текст ниже описывает то, что реально исполняется.** Механика подъёма-и-накрытия (§13.8) гейтится ДВУМЯ независимыми условиями: `prefers-reduced-motion` (§ Scroll Progress and Layering) И `matchMedia('(max-width: 767px)')` — `index.html` явно вызывает `stopMotion()` на мобильной ширине и `startMotion()` выше 767px, с `addEventListener('change', …)` на переход через границу при ресайзе/повороте экрана. То есть `.js-stage-active` **не добавляется на мобильной ширине вообще**, независимо от `prefers-reduced-motion` — сцены на мобильном всегда в baseline-режиме (обычный поток документа, без подъёма). Меняется внутренняя раскладка сцены на обеих ширинах:

* **Desktop / tablet (`> 760px`)** — полноэкранная фотография, текст в свободной зоне поверх неё (§ Content Safe Zones, §13.9). На планшетной ширине (`761–1100px`) у Namaste/Tracker номер проекта закреплён на `top: 28px`, отдельно от рекомендованного заголовку центрирования — иначе на более низком боксе они визуально соприкасаются.
* **Mobile (`≤ 760px`)** — `object-fit: cover` на пейзажной фотографии в узкой портретной рамке почти не оставляет свободного поля по бокам (подтверждено вживую: полноширинный текст поверх фото на 375px читался прямо по планшету/телефону). Вместо дальнейшего сужения текстовой колонки внутри фото сцена делится по горизонтали внутри того же абсолютно позиционированного слоя: изображение занимает верхние ~56% сцены, текст — на сплошной подложке (`var(--surface)`) в нижних ~44%, тёмный текст на светлом фоне, единая тёмная CTA-кнопка (`rgba(23,17,14,.9)`/`#f8f8f8`) для всех четырёх проектов вместо четырёх разных инверсий. Сам слой (`.project-showcase`) остаётся `position: absolute; inset: 0` — механика подъёма не знает и не обязана знать о внутренней раскладке.
* Текст/анимация — упрощённый одиночный фейд через `--mobile-text-o` (полоса локального прогресса 0.40–0.65) вместо десктопного четырёхшагового стаггера (`--header-o`/`--desc-o`/`--cta-o`) — меньше отдельных порогов для быстрой и неравномерной мобильной прокрутки, при этом сам подъём сцены не упрощается.

## 21. Reduced motion

Обязательно поддерживать:

```css
@media (prefers-reduced-motion: reduce)
```

В этом режиме:

* отключить постоянное движение по орбитам;
* показать логотипы в исходных положениях;
* `.js-stage-active` не добавляется вовсе — стек проектных сцен остаётся в baseline-состоянии: `.projects-stage-wrap` обычной высоты, каждая `.project-showcase` — обычная статичная full-bleed секция в потоке документа, без подъёма, без масштабирования обложки, без параллакса;
* показать контент без stagger — весь текст и кнопка видны сразу (`opacity: 1`, без `transform`);
* сохранить все элементы и действия доступными, включая переход в кейс по клику/Enter.

## 22. Доступность

* Использовать семантические ссылки и кнопки.
* Сохранять клавиатурную навигацию.
* Добавлять заметный `:focus-visible`.
* Для содержательных изображений использовать осмысленный `alt`.
* Декоративные орбиты скрывать от скринридеров.
* Не полагаться только на цвет.
* Сохранять достаточный контраст.
* Не скрывать информацию до бесконечности при ошибке JavaScript.
* Обеспечить работу основных ссылок без анимаций.

## 23. Производительность

* Предпочитать CSS и лёгкий JavaScript.
* Не устанавливать тяжёлую animation-библиотеку без необходимости.
* Использовать один общий `requestAnimationFrame` для орбит.
* Останавливать анимацию при скрытии вкладки.
* Оптимизировать обложки без заметной потери качества.
* Задавать размеры изображений заранее.
* Исключить cumulative layout shift.
* Не анимировать layout-свойства, если можно использовать `transform` и `opacity`.

## 24. Запрещённые паттерны

Не использовать:

* весь SVG как одну полноэкранную картинку;
* статичные SVG-пути вместо рабочих ссылок;
* случайные цвета логотипов как UI-палитру;
* сине-фиолетовые AI-градиенты;
* вложенные карточки;
* чрезмерные blur и glow;
* жёсткие тени;
* bounce и elastic easing;
* scroll hijacking;
* обязательный scroll snap;
* автозапуск аудио;
* декоративную анимацию без функционального смысла;
* изменение текстов и ссылок без подтверждения;
* дублирование информации проекта под полноэкранной сценой;
* изменение страниц кейсов при работе только над главной.

## Case navigation (Home/Prev + Next case)

**Исправлено 2026-08-28 — предыдущая версия этого раздела описывала лайк-функцию (сердце, `localStorage`-счётчик, `LikesStore`), которая никогда не была реализована в коде; UI-аудит это обнаружил и раздел переписан под то, что реально существует.** `.case-floating-nav` — `position: fixed`, два самостоятельных glass-контрола без общего фона. Левый контрол не одинаков на всех четырёх страницах: `case-alif-partners.html` (первый кейс в цикле) показывает `.case-home` (ссылка на `index.html`), а `case-eaj-trader.html`/`case-namaste.html`/`case-360-tracker.html` показывают `.case-prev` (ссылка на предыдущий по циклу кейс) — так у первого кейса нет обратной ссылки «на кейс перед Alif», вместо этого он ведёт на главную. Правый контрол везде одинаков — `.case-next`. Никакой функции «лайка» на сайте нет.

Разметка `.case-floating-nav` добавлена в конец всех четырёх страниц кейсов — внутри `.page`, сразу после `.case-page` и перед lightbox-разметкой. Отдельного `<footer>` на страницах кейсов нет.

```html
<!-- case-alif-partners.html — первый кейс: Home + Next -->
<nav class="case-floating-nav">
  <a class="case-home" href="index.html">← Главная страница</a>
  <a class="case-next" href="case-eaj-trader.html">Следующий кейс — EAJ Trader →</a>
</nav>

<!-- case-eaj-trader.html / case-namaste.html / case-360-tracker.html — Prev + Next -->
<nav class="case-floating-nav">
  <a class="case-prev" href="case-alif-partners.html">← Предыдущий кейс — Alif Partners</a>
  <a class="case-next" href="case-namaste.html">Следующий кейс — Namaste →</a>
</nav>
```

**Glassmorphism.** Формула стекла для `.case-home`/`.case-prev`/`.case-next` — см. §13.3. Больше нигде на сайте стекло не применяется, кроме главного экрана (§13.1).

**Состояния.** `.case-home`/`.case-prev`/`.case-next` — те же принципы, что у `.contact-btn`/`.project-showcase__cta`: капсульная форма (`--radius-pill`), `min-height: 56px` на desktop (`48px` на mobile), заметный `:focus-visible` (outline, не box-shadow), плавный hover (фон контрастнее, стрелка `.case-next__arrow`/`.case-prev__arrow`/`.case-home__arrow` смещается), `:active` — `scale(0.96)` без bounce/elastic.

**Циклический порядок кейсов**:
```text
Alif Partners → EAJ Trader → Namaste → 360 Tracker → Alif Partners
```
Ссылка и название следующего кейса — статический `<a href>` прямо в HTML каждой страницы; работает полностью без JavaScript. `assets/case-nav.js` не хранит эту последовательность и не строит навигацию динамически — оно отвечает только за auto-hide верхней навигации при скролле (см. ниже) и за entrance-анимацию дока.

**RU/EN.** Подписи (`Главная страница`/`Homepage`, `Предыдущий кейс`/`Previous case`, `Следующий кейс`/`Next case`) — те же пары `data-lang="ru"/"en"` спанов, что и везде на сайте; переключаются чистым CSS-тогглом, без отдельной JS-логики для этого блока.

**Появление и no-JS.** `.case-floating-nav` без класса `is-inview` уже видим и функционален (fallback-стили не завязаны на `opacity: 0`) — JS лишь добавляет одноразовый fade+translateY при загрузке (не scroll-triggered, см. §13.3), без `prefers-reduced-motion` — мгновенно. Панель — `position: fixed` и намеренно может лежать поверх контента при скролле; безопасная зона обеспечивается отступом `.case-page` (§13.2) плюс, на низких viewport-высотах (≤820px), компактной версией вертикальных отступов над `.case-context-cards` (см. `@media (max-height: 820px)` в каждом кейс-файле) — иначе на распространённых ноутбучных экранах (1280×720, 1366×768) верхняя часть страницы физически доходит до зоны дока.

**Mobile.** Обе капсулы остаются в одном ряду (`.case-floating-nav`, `flex`, `gap: 8px`); `.case-next__label`/`.case-prev__label` скрываются визуально (см. §13.3), название кейса не обрезается; минимальная интерактивная область — `48px`.

**Reduced motion.** `@media (prefers-reduced-motion: reduce)` отключает entrance-fade дока и движение стрелки при hover — переход по обеим ссылкам остаётся полностью доступен.

**Верхняя навигация на всех 6 страницах.** `assets/case-nav.js`, помимо дока на страницах кейсов, отвечает за `initNavAutoHide()` — скрывает `.site-nav` (класс `.is-nav-hidden`) при скролле вниз (после 120px) и возвращает при скролле вверх или при фокусе внутри неё; это единственная функция скрипта на страницах без дока. Скрипт подключён на всех 6 страницах, включая `index.html` — до фикса аудита 2026-08-28 `index.html` не подключал `case-nav.js` вовсе, поэтому верхняя навигация там не скрывалась при скролле (несогласованно с остальными 5 страницами) и на мобильном перекрывала текст проектных сцен без возможности убрать её со своего пути.
